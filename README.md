# music-convert

Convert a directory tree of FLAC files into an equivalent directory tree of Opus files for
playback on phones or laptops that don't have lots of space.

The tool also handles the lossy files in your collection. Non-FLAC audio files are copied
directly to the output directory, preserving their relative paths, and their embedded album
art is resized and re-embedded the same way it is for converted FLACs.

Supported input formats are **FLAC, MP3, Opus, and Ogg Vorbis**. Extension matching is
case-insensitive, including for FLAC files.

This is the Python rewrite of the original `music-convert.sh` shell script. It supports both
one-shot conversion and a long-running watch mode.

## How it works

- FLAC files are encoded to Opus with `opusenc` at 96 kbps, downmixed to stereo.
- MP3, Opus, and Ogg Vorbis files are copied with their audio untouched. Only their embedded
  artwork is replaced.
- Album art is resized with ImageMagick to fit within 500x500 and compressed to under 100 KB.
  A single `cover.jpg` is placed beside the tracks in each album directory.
- For each track, embedded artwork is preferred; if a track has none, the album's external
  cover is used. The shared `cover.jpg` prefers an external cover found in the source
  directory (`cover.*`, `folder.*`, or album artist/album names).
- Unrelated files in the output directory are left alone. Outputs that were generated by the
  tool are removed when their source files disappear, so the output stays a mirror of the
  library.

The Python tool records what it has generated in a small SQLite database so it can tell the
difference between "not built yet", "up to date", and "the source changed". A file being
modified — including a tag-only change — changes its size and/or modification time, which
triggers a rebuild of the corresponding output.

## Dependencies

- **Python 3.11+**
- **mutagen** (metadata and artwork for all supported formats)
- **inotify-simple** (watch mode)
- **opusenc** (Fedora package: `opus-tools`)
- **ImageMagick** (`magick`; Fedora package: `ImageMagick`)

Install the Python dependencies with:

```sh
python3 -m pip install -r requirements.txt
```

## Usage

One-shot conversion:

```sh
./music-convert /path/to/input/library /path/to/output/library
```

Watch mode, which performs an initial conversion and then keeps the output in sync:

```sh
./music-convert --watch /path/to/input/library /path/to/output/library
```

For all options, see `./music-convert -h`:

```
  -j, --jobs JOBS           number of concurrent jobs (default: CPU count)
  -q, --quiet               only log warnings and errors
  -y, --yes                 skip the confirmation prompt
      --watch               run continuously and keep the output in sync using inotify
      --dry-run             show planned changes without modifying anything
      --settle-seconds N    how long to wait for changes to settle (watch mode)
      --rescan-interval N   periodic full rescan interval in seconds (watch mode)
      --state-dir DIR       directory for persistent state
      --cache-dir DIR       directory for the artwork cache
```

The state and artwork cache default to the XDG state and cache directories and are keyed by
the output path.

## Watch mode

Watch mode uses Linux inotify, but inotify only signals *that* something may have changed.
The real work is done by a reconciliation pass that scans the source tree, compares it against
the recorded state, and rebuilds what changed. That reconciliation is run after a short
debounce, on a timer, and whenever inotify reports that its event queue overflowed. This means
the output converges even if events are missed, the daemon restarts, or files are written
slowly.

A few notes:

- Source and output directories must be local and must not overlap.
- A quiet period cannot prove that another program has finished writing a file. Stability
  checks and re-scans make the tool converge once writes stop, but it is not a transactional
  snapshot of a library that is being actively edited.
- If two sources would produce the same output path (for example `song.flac` and `song.opus`),
  the collision is reported and both files are skipped.

### Running as a service

A systemd user unit is provided in `contrib/music-convert.service`. Adjust the paths, install
it to `~/.config/systemd/user/`, then:

```sh
systemctl --user daemon-reload
systemctl --user enable --now music-convert.service
journalctl --user -u music-convert -f
```

Enable lingering (`loginctl enable-linger "$USER"`) if you want it to run without an active
login session.

## ReplayGain

`opusenc` applies per-track ReplayGain as it encodes. To add album gain, run
[r128gain](https://github.com/desbma/r128gain) over the converted FLAC outputs afterwards.
Note that watch mode will not preserve tag edits you make directly to generated FLAC outputs;
changes should be made to the source library instead.

## Development

Run the integration tests, which build real audio fixtures with ffmpeg and exercise one-shot
conversion, tag changes, deletions, dry runs, and watch mode:

```sh
python3 tests/test_integration.py
```

The test suite requires `ffmpeg` in addition to the runtime dependencies.
